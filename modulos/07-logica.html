Lógica: decisiones, ramas y bucles

Hasta ahora tus workflows iban en línea recta. En la vida real hay que decidir: si el pedido está pagado, envíalo; si no, recuerda el pago. En este módulo aprenderás a dividir el camino con IF y Switch, a quedarte solo con lo que te interesa con Filter, a volver a juntar los datos con Merge y a repetir pasos con Loop Over Items.

Basado en la documentación y el código de n8n 2.x (estable 2.49.7 en noviembre de 2026). Versiones de nodo usadas: If 2.4, Switch 3.5, Filter 2.4, Merge 3.2, Loop Over Items 3 y Wait 1.1.

Ramas: cuando el workflow se divide

Algunos nodos tienen más de una salida. Cada salida es el comienzo de una rama: un camino distinto del workflow. Cada item sale solo por la salida que le corresponde.

Entran 6 pedidos

101 · pagado102 · sin pagar103 · pagado104 · pagado105 · pagado106 · sin pagar

¿pagado?

Salida false (2)

Tres reglas que conviene recordar:

  • Una rama sin items no se ejecuta. Si ningún pedido está sin pagar, los nodos de la rama false simplemente no corren.
  • Las ramas se ejecutan una detrás de otra, no a la vez: n8n termina una rama antes de empezar la siguiente, de la que está más arriba en el lienzo a la de más abajo (a igual altura, primero la de la izquierda).
  • Mover nodos cambia el orden en que se ejecutan las ramas. Casi nunca importa, pero tenlo en cuenta si una rama depende de otra.

IF: dos caminos, sí o no

El nodo If comprueba una o varias condiciones con cada item. Si se cumplen, el item sale por true; si no, por false. Es el «si… entonces… si no…» de n8n.

Sus parámetros

  • ConditionsCada condición tiene tres partes: el valor a comprobar (normalmente una expresión como {{ $json.pagado }}), el tipo y la comparación (is true, is greater than…) y, si hace falta, el valor con el que comparar.
  • AND / ORCon varias condiciones eliges cómo se combinan: AND exige que se cumplan todas; OR, que se cumpla al menos una.
  • Convert types where requiredSi el valor no es del tipo de la comparación (un número que llega como texto, "120"), n8n intenta convertirlo en lugar de dar error.
  • Ignore CaseOpción para no distinguir mayúsculas de minúsculas al comparar textos. Viene activada.

Arrastra el campo desde el panel Input hasta el primer hueco de la condición: n8n escribe la expresión y, muchas veces, elige ya el tipo correcto.

Tipos y comparaciones

Cada comparación pertenece a un tipo de dato. Elige el tipo que tiene el campo de verdad, no el que parece: 120 es un número, pero "120" es un texto.

TipoComparaciones más usadasEjemplo

Numberis equal to, is greater than, is less than, is greater than or equal to, is less than or equal to{{ $json.importe }} is greater than or equal to 100

El error más común: tipos que no coinciden

Por defecto, n8n es estricto. Si comparas un texto con una comparación de números, el nodo se detiene con un error como este:

Error del nodo If
Wrong type: 'ES' is a string but was expecting a number [condition 0, item 0]

Tienes tres salidas: elegir el tipo correcto, convertir el valor en la expresión ({{ $json.importe.toNumber() }}) o activar Convert types where required. Pruébalo en el enrutador de abajo.

Switch: más de dos caminos

Cuando hay más de dos opciones (país, tipo de cliente, prioridad…), encadenar varios If se vuelve un lío. El nodo Switch tiene una salida por cada regla.

  • Mode: RulesEscribes una regla por salida, con las mismas condiciones que el If. Es el modo habitual.
  • Mode: ExpressionUna expresión devuelve directamente el número de la salida (0, 1, 2…). Útil si ya tienes ese número en los datos.
  • Rename OutputPon nombre a cada salida («España», «Portugal»). El nombre se ve en el lienzo y hace el workflow mucho más legible.
  • Fallback OutputQué hacer con los items que no cumplen ninguna regla: None (se descartan, la opción por defecto), Extra Output (una salida más) o mandarlos a la salida de una regla.
  • Send data to all matching outputsPor defecto, un item sale solo por la primera regla que cumple. Con esta opción sale por todas las que cumpla.

Si dejas Fallback Output en None, los items que no encajan en ninguna regla desaparecen sin avisar. Para no perder nada, usa Extra Output y conecta algo a esa salida.

Filter: quedarte solo con lo que interesa

El nodo Filter usa las mismas condiciones que el If, pero tiene una sola salida: deja pasar los items que cumplen y descarta el resto.

Usa If

Cuando los items que no cumplen también tienen que hacer algo (recordar el pago, avisar de un error).

Usa Filter

Cuando los que no cumplen sobran: «solo los emails con adjunto», «solo los pedidos de más de 50 €». El workflow queda más limpio.

Si Filter descarta todos los items, los nodos siguientes no se ejecutan: es una forma limpia de parar el workflow cuando no hay nada que hacer.

Merge: volver a juntar los datos

    
El nodo Merge tiene varias entradas (2 por defecto, hasta 10 con Number of Inputs) y una salida. Sirve para dos cosas distintas: reunir las ramas que se separaron con If o Switch, y combinar datos de dos fuentes (pedidos y clientes, por ejemplo).

Bucles: repetir pasos

    
Buena noticia: casi nunca necesitas un bucle. Como viste en el módulo 5, cada nodo se ejecuta una vez por item automáticamente. Si llegan 50 contactos a un nodo de Gmail, envía 50 emails.

    
Los bucles hacen falta en casos concretos:

    
    
      
  • Límites de una API: enviar de 10 en 10, con una pausa entre lotes, para no superar el máximo de peticiones por minuto.
    • 
      
  • Nodos que no recorren todos los items: algunas operaciones se ejecutan una sola vez, como el nodo Code en modo Run Once for All Items, RSS Read (una vez por URL pedida) o algunas inserciones en bases de datos.
    • 
      
  • Repetir hasta que se cumpla algo: pedir páginas a una API hasta que no queden más.
    • 
    

    
Loop Over Items

    
El nodo Loop Over Items (antes Split in Batches) reparte los items en lotes y los pasa de uno en uno. Tiene dos salidas:

    
    
      
  • loopSale un lote en cada vuelta. Aquí conectas lo que quieras repetir, y el último nodo de la vuelta se conecta otra vez a la entrada de Loop Over Items.
    • 
      
  • doneCuando no quedan lotes, sale todo lo procesado junto. Aquí sigue el workflow.
    • 
      
  • Batch SizeCuántos items por lote (1 por defecto).
    • 
      
  • ResetOpción para que cada vuelta trate la entrada como un conjunto nuevo. Se usa en bucles «hasta que…» con un If; si la condición de salida nunca se cumple, el bucle no termina.
    • 
    

    

      Loop Over ItemsBatch Size: 2
      

        
loop → Wait (1 s) → Marcar enviado → vuelve a Loop Over Items ↺

        
done → Pedidos listos (todos los items juntos)

      

    

    
Para un bucle «hasta que…» sin Loop Over Items, conecta la salida de un nodo a la entrada de otro anterior y pon un If que decida si se vuelve atrás o se sale. Asegúrate de que la condición de salida llegará a cumplirse.

Problemas frecuentes

    

      
«Wrong type: '…' is a string but was expecting a number»
El campo es texto y la comparación es de números (o al revés). Elige el tipo correcto, convierte en la expresión con .toNumber() o activa Convert types where required.

      
Los nodos de una rama no se ejecutan
Esa rama no recibió ningún item: es normal. Si necesitas que siga aunque no haya datos, activa Always Output Data en la pestaña Settings del nodo anterior (sale un item vacío) y tenlo en cuenta en los nodos siguientes.

      
Faltan items después de un Switch
No cumplían ninguna regla y Fallback Output estaba en None, así que se descartaron. Usa Extra Output. Si esperabas que un item fuera por varias salidas, activa Send data to all matching outputs.

      
Merge con Matching Fields no une nada
Los valores del campo no son idénticos: 1 (número) no es igual a "1" (texto), y los espacios cuentan. Revisa los tipos o activa la opción Fuzzy Compare del Merge, que trata 3 y "3" como iguales.

      
El texto «Ana» no coincide con «ana» en una condición
Revisa la opción Ignore Case del nodo (viene activada; si alguien la desactivó, las mayúsculas cuentan). Otra opción es comparar {{ $json.nombre.toLowerCase() }}.

      
El bucle no termina o se ejecuta una sola vez
Si se ejecuta una vez, el último nodo de la vuelta no está conectado de nuevo a la entrada de Loop Over Items. Si no termina, revisa la condición de salida de tu If o la opción Reset: con Reset activado, Loop Over Items vuelve a empezar con cada entrada.
