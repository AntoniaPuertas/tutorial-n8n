Datos y expresiones

Para dominar n8n tienes que entender dos cosas: cómo viajan los datos entre nodos (los items) y cómo se leen y transforman (las expresiones). En este módulo aprenderás ambas, con un laboratorio para practicar sin miedo a romper nada.

Basado en la documentación de n8n 2.x (estable 2.49.6 en noviembre de 2026). Las expresiones funcionan igual en el editor y en producción.

Todo lo que viaja son items

Los datos que pasan de un nodo a otro son siempre una lista de items. Cada item es un objeto con los datos guardados bajo la clave json y, si hay archivos (una imagen, un PDF), bajo la clave binary.

Lo que n8n guarda por dentro
[
  { "json": { "nombre": "Lucía", "ciudad": "Sevilla" } },
  { "json": { "nombre": "Jorge", "ciudad": "Bilbao" } }
]
Lo que ves en la vista JSON
[
  { "nombre": "Lucía", "ciudad": "Sevilla" },
  { "nombre": "Jorge", "ciudad": "Bilbao" }
]

El editor te ahorra la capa json: en la vista JSON ves directamente el contenido. Pero conviene saber que existe, porque reaparece en las expresiones ($('Nodo').item.json) y en el nodo Code (módulo 9).

Fíjate en las conexiones del lienzo después de ejecutar: el número que aparece sobre cada flecha («3 items») es el tamaño de esa lista.

Cada nodo trabaja item a item

Esta es la idea más importante del módulo: cuando un nodo recibe varios items, hace su trabajo una vez por cada item. No tienes que programar ningún bucle.

Entran 3 items

Lucía · SevillaJorge · BilbaoAna · Valencia
Gmail
Send email

Se envían 3 emails

Email a LucíaEmail a JorgeEmail a Ana

Por eso una misma expresión, como {{ $json.nombre }}, da un resultado distinto para cada item: en la primera vuelta vale «Lucía», en la segunda «Jorge» y en la tercera «Ana».

Esto también puede jugar en tu contra: si un nodo anterior devuelve 50 items sin que te des cuenta, el nodo de Gmail enviará 50 emails. Antes de conectar un nodo que «hace cosas» (enviar, crear, borrar), mira cuántos items le llegan.

JSON en 5 minutos

JSON es el formato de los datos en n8n. Solo tiene seis tipos de valores:

TipoEjemploCómo se lee en una expresión
Texto (string)"nombre": "Lucía"$json.nombre
Número"precio": 49.9$json.precio
Booleano"vip": true$json.vip
Nulo"telefono": null$json.telefono
Lista (array)"compras": [49.9, 19.5]$json.compras[0] (el primero; se cuenta desde 0)
Objeto"direccion": { "ciudad": "Sevilla" }$json.direccion.ciudad

Para entrar en datos anidados, encadena puntos y corchetes: $json.pedidos[0].productos[1].nombre. Si un nombre tiene espacios, guiones o empieza por un número, usa corchetes con comillas: $json["nombre completo"].

Qué es una expresión

Una expresión es un trocito de código, muy parecido a JavaScript, que escribes dentro de un parámetro entre {{ }}. n8n lo calcula en el momento de ejecutar, para cada item.

  • HolaValor fijo: siempre «Hola».
  • {{ $json.nombre }}Expresión: el campo nombre del item que se está procesando.
  • Hola, {{ $json.nombre }}Texto fijo y expresión mezclados: «Hola, Lucía», «Hola, Jorge»…
  • {{ $json.precio * 2 }}También se puede calcular: suma, resta, multiplica, compara…

Cómo se escribe en el editor

  1. Activa el modo expresión. Pasa el ratón sobre el parámetro y elige Expression en el selector Fixed | Expression. También puedes arrastrar un campo desde el panel Input: n8n escribe la expresión por ti.
  2. Escribe entre llaves. Al teclear dentro de {{ }}, el editor te sugiere variables y funciones. Pulsa Enter o Tab para aceptar una sugerencia.
  3. Mira la vista previa. Debajo del campo aparece el resultado calculado con los datos de entrada. Si hay un error, lo verás ahí antes de ejecutar nada.
  4. Amplía el editor si la expresión es larga: el icono de expandir del campo abre un editor más grande con la entrada, la expresión y el resultado a la vez.

La vista previa necesita datos de entrada. Si el nodo anterior no se ha ejecutado nunca, n8n no puede calcularla: ejecuta antes los nodos anteriores (o fija sus datos con Pin data).

Variables que más vas a usar

Dentro de una expresión tienes variables que empiezan por $. Estas son las imprescindibles:

VariableQué devuelve
$jsonLos datos del item actual que llega del nodo anterior. Es la que usarás el 90 % de las veces.
$('Nombre del nodo').item.jsonLos datos del item relacionado en un nodo anterior, aunque no esté conectado justo antes.
$('Nombre del nodo').first().jsonLos datos del primer item de ese nodo. Útil para configuración que solo tiene un item.
$('Nombre del nodo').last() / .all()El último item / todos los items de ese nodo (una lista).
$input.all()Todos los items que entran en el nodo actual.
$now / $todayLa fecha y hora actuales / el día de hoy a las 00:00, en la zona horaria del workflow.
$workflow.name / $execution.idEl nombre del workflow / el identificador de la ejecución. Útiles en mensajes de aviso o de error.

¿.item o .first()?

n8n sigue el rastro de cada item a través del workflow: sabe qué item de un nodo anterior dio lugar al item actual. Eso se llama item linking (enlace de items) y es lo que usa .item.

Usa .item

Cuando el nodo anterior tiene varios items y quieres el que corresponde al actual. Ejemplo: recuperar el email original del cliente que estás procesando.

Usa .first()

Cuando el nodo anterior solo tiene un item que vale para todos (una configuración, un token, un total), o cuando n8n no puede averiguar la relación y te muestra un error de item linking.

Las expresiones se refieren a los nodos por su nombre. Si renombras un nodo, n8n actualiza las expresiones que lo usan, pero si escribes un nombre a mano, tiene que coincidir exactamente (mayúsculas y tildes incluidas). Verás en foros la sintaxis antigua $node["Nodo"].json: está obsoleta, usa $('Nodo').

Funciones para transformar datos

Puedes aplicar funciones a cualquier valor con un punto, y encadenarlas: {{ $json.email.trim().toLowerCase() }}. Además de las de JavaScript, n8n añade muchas propias. Estas son las más útiles al empezar:

  • .toUpperCase() / .toLowerCase()Todo en mayúsculas / minúsculas.
  • .toTitleCase()Primera letra de cada palabra en mayúscula: «lucía martín» → «Lucía Martín».
  • .trim()Quita los espacios del principio y del final.
  • .split(' ')Corta un texto y devuelve una lista: "lucía martín".split(' ')[0] → «lucía».
  • .replace('a', 'b')Sustituye un texto por otro (la primera vez que aparece; .replaceAll() para todas).
  • .isEmail() / .extractEmail()Comprueba si es un email / saca el email de un texto más largo.
  • .isEmpty() / .isNotEmpty()Comprueba si está vacío.
  • .round(2)Redondea a 2 decimales: 83.974 → 83.97.
  • .floor() / .ceil()Redondea hacia abajo / hacia arriba.
  • .toLocaleString('es-ES')Formato español para mostrar: 1234.5 → «1.234,5».
  • .isEven() / .isOdd()¿Es par? / ¿Es impar?
  • "12".toNumber()Convierte un texto en número para poder calcular.
  • .lengthCuántos elementos tiene (sin paréntesis).
  • .first() / .last()El primer / último elemento.
  • .sum() / .average()Suma / media de una lista de números.
  • .min() / .max()El valor más pequeño / más grande.
  • .join(', ')Une los elementos en un texto: ["a","b"] → «a, b».
  • .unique()Quita los repetidos.

Las fechas de n8n usan la librería Luxon y respetan la zona horaria del workflow.

  • $now.toFormat('dd/MM/yyyy')Fecha de hoy al estilo español: «26/11/2026».
  • $now.toFormat('HH:mm')La hora: «12:37».
  • $today.minus({ days: 7 })Hace una semana (a las 00:00).
  • $today.plus({ months: 1 })Dentro de un mes.
  • $json.fecha.toDateTime()Convierte un texto de fecha (por ejemplo "2026-03-14") en una fecha con la que operar.
  • {{ $json.vip ? 'VIP' : 'Estándar' }}Operador ternario: condición ? si es verdad : si es falso.
  • {{ $json.telefono ?? 'Sin teléfono' }}Valor por defecto si el campo no existe o es nulo.
  • {{ $json.direccion?.ciudad }}El ?. evita un error si direccion no existe: devuelve vacío en lugar de fallar.
  • {{ $json.total > 100 }}Comparaciones: devuelven true o false.

Para decisiones que cambian el camino del workflow, usarás los nodos IF y Switch (módulo 7).

No hace falta memorizarlas: al escribir un punto detrás de un valor, el editor te muestra las funciones disponibles para ese tipo de dato, con una breve explicación.

    Problemas frecuentes
    
    
    
      
    La vista previa sale vacía o como undefined
    El campo no existe con ese nombre en el item. Revisa mayúsculas, tildes y el nivel de anidamiento (¿es $json.ciudad o $json.direccion.ciudad?). Lo más seguro es arrastrar el campo desde el panel Input en lugar de escribirlo.
    
      
    «Cannot read properties of undefined (reading '…')»
    Intentas aplicar una función o entrar en un campo de algo que no existe, por ejemplo $json.telefono.trim() en un cliente sin teléfono. Usa ?. y ??: {{ $json.telefono?.trim() ?? 'Sin teléfono' }}.
    
      
    Error de item linking: «Info for expression missing from previous node»
    n8n no puede averiguar qué item del nodo anterior corresponde al actual (suele pasar después de nodos Code o de algunos nodos de la comunidad). Si el nodo referenciado tiene un solo item, cambia .item por .first(). Si tiene varios, usa .all()[índice] o revisa el diseño del workflow.
    
      
    La vista previa dice que no hay datos o que el nodo no se ha ejecutado
    Las expresiones necesitan datos de ejemplo para la vista previa. Ejecuta los nodos anteriores (Execute previous nodes) o el workflow completo. El cálculo real siempre se hace al ejecutar.
    
      
    Un número sale como texto y no puedo sumarlo
    Viene entre comillas en el JSON ("12"). Conviértelo con .toNumber() o pon el campo de tipo Number en Edit Fields, que lo convierte al guardar.
    
      
    Copié una expresión de un foro y usa $node["…"] o $items()
    Es sintaxis antigua. Tradúcela: $node["Nodo"].json → $('Nodo').item.json, y $items("Nodo") → $('Nodo').all().
