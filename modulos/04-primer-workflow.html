Tu primer workflow

En el módulo anterior pegaste un workflow ya hecho. Ahora lo vas a construir tú desde cero: un trigger manual y dos nodos Edit Fields que crean los datos de un pedido y preparan un resumen.

Qué vas a construirLas piezasEdit Fields a fondoSimuladorPaso a pasoSoluciónProblemas frecuentesRetosTest

Este módulo usa n8n 2.x (la versión estable en noviembre de 2026 es la 2.49.6) y la versión 3.4 del nodo Edit Fields. Si ya usas n8n 3.x, los pasos son los mismos, aunque algún texto de la interfaz puede cambiar.

Qué vas a construir

Un workflow de tres nodos que simula la llegada de un pedido y prepara un resumen listo para enviar por email o guardar en una hoja de cálculo. Más adelante cambiarás el trigger manual por un formulario o un webhook, pero la idea será la misma.

Al ejecutarlo, el último nodo devolverá esto:

Salida de «Preparar resumen» (vista JSON)
[
  {
    "cliente": "Lucía Martín",
    "total": 99.8,
    "mensaje": "Pedido de Lucía Martín: 2 x Curso de n8n (99.8 €)"
  }
]

¿Por qué empezar así? Porque casi todos los workflows reales siguen este patrón: algo dispara el workflow, se preparan los datos y se hace algo con ellos. Si dominas la preparación de datos, el resto es cambiar piezas.

Las piezas que vas a usar

Manual Trigger

En el panel de nodos aparece como Trigger manually. Arranca el workflow cuando pulsas Execute workflow y nunca se ejecuta solo.

Sirve para probar un workflow antes de ponerle un trigger automático, o para tareas que quieres lanzar tú cuando quieras. Solo puede haber uno por workflow.

Edit Fields (Set)

Crea campos nuevos o sobrescribe los que ya existen. Es el nodo más usado para preparar datos: renombrar, calcular, dar formato o quedarte solo con lo que necesitas.

Está en la categoría Data transformation. Su nombre técnico es n8n-nodes-base.set, por eso a veces lo verás llamado «nodo Set».

Entre nodo y nodo viajan items. Un item es un paquete de datos en formato JSON (pares nombre: valor). El trigger manual entrega un item vacío; el primer Edit Fields lo rellena; el segundo lo lee y crea uno nuevo. En el módulo 5 veremos los items con más detalle.

El nodo Edit Fields a fondo

Dos modos de trabajo

El parámetro Mode decide cómo defines los campos:

El modo por defecto y el más cómodo para empezar. Pulsas Add Field y, para cada campo, escribes un nombre, eliges un tipo y pones un valor.

También puedes arrastrar un campo desde el panel Input: n8n crea un campo con el mismo nombre y, como valor, una expresión que lee ese dato (por ejemplo {{ $json.cliente }}).

Escribes directamente el objeto JSON que quieres añadir. Es más rápido cuando hay muchos campos, listas u objetos anidados, y también admite expresiones.

Ejemplo en modo JSON
{
  "cliente": "Lucía Martín",
  "precio": 49.9,
  "etiquetas": ["formación", "online"]
}

El JSON tiene que ser válido: comillas dobles en nombres y textos, y sin coma tras el último campo.

Tipos de campo

En Manual Mapping, cada campo tiene un tipo. El tipo importa: el número 2 se puede sumar, pero el texto "2" no.

TipoPara quéEjemplo de valor
StringTextoLucía Martín
NumberNúmeros con los que vas a calcular. El decimal se escribe con punto49.9
BooleanSí o notrue / false
ArrayUna lista de valores, en formato JSON["formación", "online"]
ObjectUn grupo de campos, en formato JSON{"ciudad": "Sevilla"}

Valor fijo o expresión

Si pasas el ratón por encima de un valor aparece el selector Fixed | Expression:

  • Fixed (fijo): el valor es exactamente lo que escribes. Lucía Martín siempre será Lucía Martín.
  • Expression: lo que va entre {{ }} se calcula al ejecutar. {{ $json.precio * $json.cantidad }} multiplica dos campos del item que llega. Debajo del campo verás una vista previa del resultado.

En este módulo solo usarás expresiones sencillas del tipo $json.campo. Las expresiones tienen su propio módulo, el 5.

¿Qué pasa con los campos que ya traía el item?

Por defecto, Edit Fields devuelve solo los campos que defines y descarta el resto. Si quieres conservarlos, activa Include Other Input Fields y elige cuáles en Input Fields to Include: todos (All), algunos (Selected) o todos menos algunos (All Except).

Es la confusión más habitual al empezar: «he añadido un campo y han desaparecido los demás». No se han perdido; simplemente el nodo no los incluye en su salida. Activa Include Other Input Fields si los necesitas más adelante.

Opciones útiles

Con el botón Add option, al final del nodo, tienes ajustes extra:

  • Support Dot NotationActivada por defecto. Un nombre con punto, como cliente.nombre, crea un objeto anidado: {"cliente": {"nombre": …}}. Si la desactivas, se crea un campo que se llama literalmente cliente.nombre.
  • Ignore Type Conversion ErrorsSi un valor no encaja con su tipo (por ejemplo, dos en un campo Number), el nodo no falla y deja el valor tal cual. Úsala con cuidado: esconde errores.
  • Include Binary FileSi el item trae archivos (imágenes, PDF…), decide si pasan al siguiente nodo.

Paso a paso en n8n

    
Abre n8n en http://localhost:5678. Esta vez no vas a pegar nada: construirás cada nodo a mano.

    
    
      
  1. Crea el workflow. En Overview, pulsa Create workflow y renómbralo como Ficha de pedido.
    2. 
      
  2. Añade el trigger. Pulsa el + del centro del lienzo, busca «manual» y elige Trigger manually. Selecciónalo, pulsa F2 y llámalo Al pulsar Ejecutar.
    3. 
      
  3. Añade el primer Edit Fields. Pulsa el + que sale a la derecha del trigger, busca «edit fields» y elige Edit Fields (Set). Se abre su vista de detalle. Haz clic en el título del nodo y renómbralo como Datos del pedido.
    4. 
      
  4. Define los campos. Deja Mode en Manual Mapping. Pulsa Add Field y crea estos seis campos, eligiendo el tipo en el desplegable de cada uno:
        
    
          
    NombreTipoValor
    
          
            
    clienteStringLucía Martín
    
            
    productoStringCurso de n8n
    
            
    precioNumber49.9
    
            
    cantidadNumber2
    
            
    pagadoBooleantrue
    
            
    etiquetasArray["formación", "online"]
    
              
        
    
      
    5. 
      
  5. Prueba el nodo. Pulsa Execute step (arriba, en la vista de detalle). En Output verás tu item. Cambia a la vista JSON y comprueba que precio y cantidad salen sin comillas (son números) y que etiquetas es una lista.
    6. 
      
  6. Añade el segundo Edit Fields. Cierra la vista de detalle, pulsa el + a la derecha de «Datos del pedido», añade otro Edit Fields (Set) y llámalo Preparar resumen. Ahora el panel Input de la izquierda muestra los seis campos del nodo anterior.
    7. 
      
  7. Arrastra un campo. En el panel Input, en vista Schema, arrastra cliente hasta la zona Fields to Set y suéltalo. n8n crea el campo cliente con el valor {{ $json.cliente }} en modo Expression.
    8. 
      
  8. Calcula el total. Pulsa Add Field: nombre total, tipo Number. Pasa el valor a modo Expression (selector Fixed | Expression) y escribe {{ $json.precio * $json.cantidad }}. La vista previa debe mostrar 99.8.
    9. 
      
  9. Escribe el mensaje. Añade un campo mensaje de tipo String, en modo Expression, con este valor:
        
    Valor del campo «mensaje»
    Pedido de {{ $json.cliente }}: {{ $json.cantidad }} x {{ $json.producto }} ({{ $json.precio * $json.cantidad }} €)
    
        Fíjate en que puedes mezclar texto fijo y expresiones en el mismo campo.
    10. 
      
  10. Ejecuta el workflow completo. Cierra la vista de detalle y pulsa Execute workflow (Ctrl + Enter). Los tres nodos se ponen en verde y cada conexión muestra «1 item». Abre «Preparar resumen» y comprueba que la salida coincide con la del principio del módulo.
    11. 
      
  11. Prueba Include Other Input Fields. En «Preparar resumen», activa Include Other Input Fields (con All) y pulsa Execute step: ahora la salida tiene nueve campos. Vuelve a desactivarlo para quedarte solo con el resumen.
    12. 
      
  12. Guarda una copia. El workflow ya se ha guardado solo. Aun así, descárgalo como archivo desde el menú ⋯ de la cabecera → Download. Así tendrás una copia de tu primer workflow.
    13. 
    

    
Este workflow no necesita publicarse: empieza con un trigger manual, así que solo se ejecuta cuando tú lo pulsas. En el módulo 6 lo cambiarás por un trigger automático y entonces sí lo publicarás.

Problemas frecuentes

    

      
Error: el campo «expects a number» al ejecutar
Has puesto en un campo Number algo que no es un número. Lo más típico en español: escribir el decimal con coma (49,9). Usa punto: 49.9.

      
En la salida aparece el texto {{ $json.cliente }} tal cual
El campo está en modo Fixed. Pasa el ratón por encima del valor y cambia a Expression. En modo expresión el campo cambia de aspecto y muestra una vista previa debajo.

      
La vista previa de la expresión sale vacía o en rojo
Revisa dos cosas: que el nombre del campo está bien escrito (Cliente y cliente son distintos) y que el nodo anterior se ha ejecutado al menos una vez. Si no hay datos de entrada, n8n no puede calcular la vista previa: pulsa Execute previous nodes o ejecuta el workflow.

      
He añadido un campo y han desaparecido todos los demás
Es el comportamiento por defecto: Edit Fields solo devuelve los campos que defines. Activa Include Other Input Fields para conservar el resto.

      
Error al crear un campo Array u Object
El valor debe ser JSON válido: ["formación", "online"] con comillas dobles. Con comillas simples (['formación']) falla.

      
«Only one 'Manual Trigger' node is allowed in a workflow»
Tienes dos triggers manuales, por ejemplo porque has pegado la solución sobre tu propio workflow. Borra uno de los dos.

Reto 2 · Modo JSON
Duplica «Datos del pedido» (Ctrl + C / Ctrl + V), cambia el Mode a JSON y consigue exactamente la misma salida escribiendo el objeto a mano.
