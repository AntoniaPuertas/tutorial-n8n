El proyecto

Lumen es una tienda online de lámparas (inventada). Hoy los clientes escriben a un email que nadie revisa a tiempo: los cobros duplicados se mezclan con preguntas sobre colores y las urgencias se pierden. Te piden esto:

  1. Un formulario de contacto con nombre, email, número de pedido (opcional) y mensaje.
  2. Clasificación automática de cada mensaje: tema (envío, devolución, pago, producto u otro), urgencia (alta, media o baja), un resumen corto y un borrador de respuesta.
  3. Un registro de todas las incidencias con un número de ticket.
  4. Un aviso inmediato cuando algo es urgente.
  5. Un resumen cada mañana con lo que entró en las últimas 24 horas.
  6. Que nada se pierda: si la IA falla, el mensaje se guarda igualmente para revisarlo a mano; si un workflow se rompe, llega un aviso.

¿Por qué una Basic LLM Chain y no un AI Agent? Porque clasificar un mensaje es una pregunta al modelo: no hace falta conversar, ni memoria, ni herramientas. Es más barato, más rápido y más predecible (módulo 10).

El plan

Antes de abrir n8n, un profesional dibuja el sistema, decide qué datos guarda y prepara casos de prueba. Este es el plan.

Tres workflows

1 · Soporte · Recibir incidencias (cada vez que alguien envía el formulario)

2 · Soporte · Resumen diario (cada mañana a las 9)

3 · Avisos de error (el del módulo 11, vigila a los otros dos)

Dividirlo en varios workflows pequeños hace que cada uno sea fácil de entender, probar y arreglar. Se comunican a través de la tabla: uno escribe y el otro lee.

    3. 
      
  3. Comprueba la credencial de Gemini del módulo 10 (Overview → Credentials). Si no la tienes, créala ahora (pestaña «Google Gemini» del módulo 10).

Fase 3 · Clasificar con IA

    
    
      
  1. Añade la cadena. Detrás de Normalizar, abre la categoría AI y elige Basic LLM Chain. Llámala Clasificar con IA.
    2. 
      
  2. Source for Prompt (User Message): Define below. En Prompt (User Message), en modo Expression:
        
    Prompt de «Clasificar con IA»
    Clasifica este mensaje de un cliente.

Cliente: {{ $json.nombre }}
Pedido: {{ $json.pedido || 'sin número' }}
Mensaje: {{ $json.mensaje }}
    
      
    3. 
      
  3. Instrucciones. En Chat Messages (if Using a Chat Model), añade un mensaje, deja Type Name or ID en System y escribe en Message:
        
    Mensaje de sistema
    Eres el asistente de soporte de Lumen, una tienda online de lámparas. Clasificas cada mensaje de un cliente y propones una respuesta.
- categoria: envio, devolucion, pago, producto u otro.
- urgencia: alta (cobro duplicado, producto roto o peligroso, pedido perdido más de 7 días, cliente muy enfadado), media (dudas sobre un pedido en curso, cambios y devoluciones) o baja (preguntas generales y sugerencias).
- resumen: una frase de 15 palabras como máximo.
- respuesta: borrador amable en español, de 2 a 4 frases, tuteando. No inventes datos ni prometas plazos o reembolsos concretos.
    
      
    4. 
      
  4. Modelo. En el conector Model de la cadena, añade un Google Gemini Chat Model llamado Gemini, con tu credencial, un modelo Flash y Sampling Temperature = 0.2.
    5. 
      
  5. Formato. Activa Require Specific Output Format. En el nuevo conector Output Parser, añade un Structured Output Parser llamado Formato de la respuesta con Schema Type = Generate From JSON Example y este ejemplo:
        
    JSON Example
    {
  "categoria": "envio",
  "urgencia": "media",
  "resumen": "El pedido 1051 no ha llegado y el seguimiento no avanza",
  "respuesta": "Hola, Marta: siento el retraso con tu pedido. Lo estamos revisando con la empresa de transporte y te escribimos en cuanto sepamos algo."
}
    
      
    6. 
      
  6. Prueba. Ejecuta el workflow y envía el caso 1. La salida de la cadena es un item con output: {{ $json.output.categoria }} debería ser pago y {{ $json.output.urgencia }}, alta. Lee el borrador de respuesta: ¿lo enviarías tal cual?
    7. 
    

    
La IA propone, no decide. Por eso el borrador se guarda para que una persona lo revise antes de enviarlo, y el mensaje de sistema le prohíbe prometer plazos o reembolsos. Prueba los 5 casos: si alguno sale mal clasificado, mejora las definiciones de urgencia del mensaje de sistema antes de cambiar de modelo.


    
Fase 4 · Registrar la incidencia

    
    
      
  1. Preparar registro. Detrás de la cadena, un Code llamado Preparar registro en modo Run Once for Each Item, con este código:
        
    Código de «Preparar registro»
    // Se ejecuta una vez por incidencia
// Datos del formulario (normalizados) y clasificación de la IA
const f = $('Normalizar').item.json;
const ia = $json.output ?? {};   // si la IA falló, llega sin «output»

const urgencia = ['alta', 'media', 'baja'].includes(ia.urgencia) ? ia.urgencia : 'media';
const prioridad = { alta: 1, media: 2, baja: 3 }[urgencia];

return {
  ticket: 'SOP-' + $execution.id,
  nombre: f.nombre,
  email: f.email,
  pedido: f.pedido,
  mensaje: f.mensaje,
  categoria: ia.categoria ?? 'otro',
  urgencia,
  prioridad,
  resumen: ia.resumen ?? f.mensaje.slice(0, 80),
  respuesta: ia.respuesta ?? '',
  clasificado_por: ia.categoria ? 'ia' : 'pendiente'
};
    
        
    Junta en un objeto los datos del formulario (de Normalizar) y los de la IA, con valores por defecto si la IA no ha respondido. El ticket usa el número de ejecución, que es único.
    
      
    2. 
      
  2. Guardar incidencia. Añade un nodo Data table (búscalo como Data table) llamado Guardar incidencia: Resource Row, Operation Insert, Data table = incidencias (From list) y, en Columns, Map Automatically: como el Code saca exactamente las columnas de la tabla, cada campo va a su columna.
    3. 
      
  3. Prueba. Envía el caso 3. La salida de Guardar incidencia incluye las columnas automáticas id, createdAt y updatedAt. Abre la tabla en Overview → Data tables → incidencias: ahí está la fila.
    4. 
    


    
Fase 5 · Avisar de lo urgente

    
    
      
  1. ¿Urgente? Detrás de Guardar incidencia, un If llamado ¿Urgente? con la condición {{ $json.urgencia }} · String · is equal to · alta.
    2. 
      
  2. Avisar por Telegram. En la salida true, un Telegram → Send Message con tu credencial y tu Chat ID, Parse Mode HTML y Append n8n Attribution desactivado (módulo 8). Text:

{{ $json.nombre }} ({{ $json.email }})
Categoría: {{ $json.categoria }}
{{ $json.resumen }}
    
      
    3. 
      
  3. Prueba con el caso 4 (te llega el aviso) y con el caso 5 (no te llega: sale por false, que no tiene nada conectado).
    4. 
    

    
¿Sin Telegram? Pon en su lugar un Gmail (módulo 8), un No Operation como recordatorio o, simplemente, deja la rama vacía: la incidencia ya está guardada con prioridad 1 y puedes ordenar la tabla por esa columna.


    
Fase 6 · Que nada se pierda

    
Ahora toca pensar como el módulo 11: ¿qué puede fallar? Lo más probable es la IA (cuota agotada, servicio caído, una respuesta con formato raro). Si falla, no queremos perder el mensaje del cliente.

    
    
      
  1. Reintentos. En Clasificar con IA → Settings: Retry On Fail activado, Max. Tries 3 y Wait Between Tries (ms) 5000. Los errores 429 de los planes gratuitos suelen pasarse en unos segundos.
    2. 
      
  2. Rama de error. En la misma pestaña, On Error = Continue (using error output). Conecta la nueva salida Error también a Preparar registro. El Code ya está preparado: si no llega output, guarda la incidencia como otro / media con clasificado_por = pendiente.
    3. 
      
  3. Provoca el fallo. En el nodo Gemini, cambia Model a modo Expression y escribe models/no-existe. Envía el caso 1: tras los reintentos, el item sale por Error y la fila se guarda como pendiente. Deshaz el cambio.
    4. 
      
  4. Error workflow. En ⋯ → Settings, elige Avisos de error en Error Workflow. Si falla algo que no está controlado (la tabla, por ejemplo), te llegará el aviso.
    5.
