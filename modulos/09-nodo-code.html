El nodo Code

Con los nodos que ya conoces puedes hacer casi todo. Pero a veces necesitas un cálculo con varios pasos, agrupar datos o montar un informe a medida, y encadenar diez nodos se vuelve un lío. Para eso está el nodo Code: unas líneas de JavaScript (o Python) dentro del workflow, con acceso a los items y a los datos de los demás nodos.

¿Cuándo?ModosQué devolverVariablesJavaScript útilLaboratorioDepurarLímitesPythonPrácticaSoluciónProblemasTest

Basado en la documentación y el código de n8n 2.x (estable 2.49.8 a finales de noviembre de 2026): nodo Code versión 2. En n8n 2.x el código se ejecuta en un task runner, un proceso separado de n8n. No necesitas saber programar mucho: este módulo explica todo lo que usa.

¿Cuándo usar el nodo Code?

La regla de oro: primero busca un nodo que lo haga. Los nodos nativos se entienden de un vistazo en el lienzo, cualquiera puede cambiarlos y no fallan por una coma. El código es potente, pero es más difícil de leer para otra persona (o para ti dentro de tres meses).

Quiero…Nodo nativo¿Code?
Crear, renombrar o calcular un campoEdit Fields con expresionesSolo si el cálculo tiene varios pasos
Quedarme con algunos itemsFilterNo
Separar una lista en itemsSplit OutNo
Juntar items en uno, sumar o contarAggregate, SummarizeSi necesitas varios resultados a la vez
Ordenar, quitar duplicados, limitarSort, Remove Duplicates, LimitNo
Agrupar, cruzar dos listas y montar un informe con varios totalesVarios nodos encadenadosSí: aquí brilla
Llamar a una APIHTTP RequestNo: el nodo Code no tiene acceso a la red

Si con una expresión {{ }} en un Edit Fields te basta, no uses Code. Si la expresión ocupa tres líneas y te cuesta leerla, probablemente sí.

Los dos modos

Lo primero que eliges en el nodo es el Mode. Cambia cuántas veces se ejecuta tu código y qué tienes que devolver.

Run Once for All Items

El modo por defecto. Tu código se ejecuta una sola vez y recibe todos los items a la vez con $input.all().

Devuelves una lista de items: tantos como quieras (menos, más o los mismos). Úsalo para resumir, agrupar, ordenar o crear items nuevos.

Run Once for Each Item

Tu código se ejecuta una vez por item. El item actual está en $json (o $input.item).

Devuelves un objeto: el item de salida. Úsalo para transformar cada item por separado, como un Edit Fields con superpoderes.

Qué tiene que devolver tu código

Recuerda el módulo 5: cada item es un objeto con una clave json que contiene los datos. El nodo Code tiene que terminar con un return que devuelva items en ese formato.

Devolver una lista de items
// Forma completa: cada item con su clave json
return [
  { json: { cliente: 'Ana', total: 34.49 } },
  { json: { cliente: 'Jorge', total: 71.69 } }
];

// Forma corta: n8n envuelve cada objeto en { json: … } por ti
return [
  { cliente: 'Ana', total: 34.49 },
  { cliente: 'Jorge', total: 71.69 }
];

Si devuelves un único objeto, n8n lo convierte en un item. Si devuelves null, el nodo sale sin items.

Devolver un solo item
// El item actual con un campo nuevo
return {
  json: { ...$json, total_con_iva: $json.total * 1.21 }
};

// También vale sin json:
return { ...$json, total_con_iva: $json.total * 1.21 };

En este modo, si tu código no devuelve nada (o devuelve null), ese item desaparece de la salida sin ningún error. Es útil para filtrar, pero también es el despiste más común: un return olvidado y te quedas sin items.

Si el formato no es correcto, n8n para el nodo con un error. Estos son los que verás:

ErrorQué ha pasado
Code doesn't return items properlyEn All Items no has devuelto nada, o la lista contiene algo que no es un objeto (un número, un texto…).
A 'json' property isn't an objectLa clave json apunta a una lista o a un texto. En Each Item pasa también si devuelves una lista en vez de un objeto.
Invalid output formatUn item tiene json y además otras claves al lado ({ json: {...}, total: 5 }). Mete todo dentro de json.
Unknown top-level item key: …Mezclas items con json y sin él en la misma lista.
Can't use .all() hereHas usado $input.all(), .first() o .last() en Each Item. Solo existen en All Items.

Variables y métodos de n8n

Dentro del código tienes las mismas variables con $ que en las expresiones, pero sin las llaves {{ }}: aquí ya estás escribiendo JavaScript. Escribe $ en el editor y verás la lista.

  • $input.all()Todos los items de entrada, como lista. Cada uno tiene su .json. Solo en All Items.
  • $input.first() / .last()El primer o el último item de entrada. Solo en All Items.
  • $json / $input.itemEl item actual (sus datos, o el item completo). Solo en Each Item.
  • $('Nodo').all()Los items de salida de otro nodo anterior. También .first(), .last() y, en Each Item, .item (el item emparejado, como en el módulo 5).
  • $now / $todayFecha y hora actual y el día de hoy, como objetos de Luxon: $now.toFormat('dd/MM/yyyy HH:mm'). También tienes DateTime para crear fechas.
  • $workflow / $executionDatos del workflow ($workflow.name) y de la ejecución ($execution.id, $execution.mode).
  • $getWorkflowStaticData('global')Un objeto que se conserva entre ejecuciones de producción del mismo workflow. Útil para recordar, por ejemplo, el último id procesado. No se guarda en las ejecuciones manuales.
  • $jmespath(datos, consulta)Consultas sobre JSON con la sintaxis JMESPath, por si la conoces.

En código antiguo verás items (en lugar de $input.all()) e item (en lugar de $input.item). Siguen funcionando, pero en código nuevo usa las formas con $.

El JavaScript que más vas a usar

No necesitas saber todo JavaScript. Con estas piezas resuelves la mayoría de los casos:

  • lista.map(x => …)Transforma cada elemento y devuelve una lista nueva del mismo tamaño. $input.all().map(i => ({ nombre: i.json.nombre }))
  • lista.filter(x => …)Se queda con los elementos que cumplen la condición. pedidos.filter(p => p.total > 40)
  • lista.reduce((suma, x) => …, 0)Recorre la lista acumulando un resultado: sumas, totales, conteos. lineas.reduce((s, l) => s + l.unidades, 0)
  • lista.find(x => …)El primer elemento que cumple la condición (o undefined).
  • lista.sort((a, b) => b.total - a.total)Ordena; así, de mayor a menor. Ojo: modifica la lista original.
  • lista.flatMap(x => […])Como map, pero cada elemento puede dar varios: perfecto para pasar de pedidos a líneas.
  • Object.entries(obj)Convierte { Ana: 34, Jorge: 71 } en [['Ana', 34], ['Jorge', 71]] para ordenarlo o recorrerlo.
  • { ...obj, nuevo: 1 }Copia un objeto y añade o cambia campos.
  • `Hola ${nombre}`Texto con valores dentro (comillas invertidas).
  • a ?? b y a?.bValor por defecto si a no existe, y acceso seguro a algo que puede faltar (módulo 5).
  • Math.round(n * 100) / 100Redondea a 2 decimales. Imprescindible con precios: 0.1 + 0.2 da 0.30000000000000004.

Límites del nodo Code

    
    
      
  • Sin redNo puedes hacer llamadas HTTP (fetch no funciona). Pide los datos con un HTTP Request y procésalos después en el Code.
    • 
      
  • Sin discoNo puedes leer ni escribir archivos. Para eso están los nodos Read/Write Files from Disk.
    • 
      
  • MódulosPor defecto no puedes usar require. En tu instalación puedes permitir módulos de Node.js con NODE_FUNCTION_ALLOW_BUILTIN (por ejemplo crypto) y paquetes de npm con NODE_FUNCTION_ALLOW_EXTERNAL.
    • 
      
  • TiempoSi el código tarda demasiado (por defecto, 300 segundos), n8n lo corta con Task execution timed out after 300 seconds. Suele ser un bucle infinito.
    • 
      
  • LegibilidadPon un nombre claro al nodo y comentarios en el código. Quien abra el workflow solo verá «Code» en el lienzo.
    • 
    


    
¿Y Python?

    
En Language puedes elegir Python en lugar de JavaScript. En n8n 2.x es Python «nativo», que se ejecuta en un task runner de Python. Funciona igual que en JavaScript, con tres diferencias:

    
    
      
  • Los items se leen con _items (en All Items) o _item (en Each Item), y los campos con corchetes: _item["json"]["total"].
    • 
      
  • No tiene los demás ayudantes: ni $('Nodo'), ni $now, ni $input. Solo _items, _item y print() para depurar.
    • 
      
  • Por defecto no permite import, ni siquiera de la biblioteca estándar, salvo que la instalación lo autorice.
    •

Con la instalación del módulo 2 (solo el contenedor n8nio/n8n), lo más probable es que al ejecutar Python veas Python runner unavailable: Python 3 is missing from this system. Python necesita el modo externo de los task runners: un segundo contenedor, n8nio/runners, de la misma versión que n8n. Para aprender, quédate con JavaScript: es el lenguaje con más ayudantes y el que usan casi todos los ejemplos.

    
+Cómo activar Python con Docker Compose (opcional)
      
Añade un servicio para los runners al compose.yml del módulo 2 y estas variables a n8n. Ambos contenedores comparten un secreto (RUNNERS_TOKEN, que defines en el .env) y deben tener exactamente la misma versión: fija N8N_VERSION (por ejemplo, 2.49.8) en lugar de latest.

      
Fragmento de compose.yml (modo externo)
services:
  n8n:
    # … lo que ya tenías …
    environment:
      # … variables que ya tenías …
      - N8N_RUNNERS_MODE=external
      - N8N_RUNNERS_BROKER_LISTEN_ADDRESS=0.0.0.0
      - N8N_RUNNERS_AUTH_TOKEN=${RUNNERS_TOKEN}

  task-runners:
    image: n8nio/runners:${N8N_VERSION}
    container_name: n8n-runners
    restart: unless-stopped
    environment:
      - N8N_RUNNERS_TASK_BROKER_URI=http://n8n:5679
      - N8N_RUNNERS_AUTH_TOKEN=${RUNNERS_TOKEN}
    depends_on:
      - n8n

      
Después, docker compose up -d. Si algo falla, revisa los registros de los dos contenedores (docker compose logs n8n task-runners) y la página de task runners de la documentación, que es la referencia para tu versión.

    Código de «Resumen del día»
    // Se ejecuta una sola vez con todos los pedidos
const r2 = n => Math.round(n * 100) / 100;
const euros = n => n.toFixed(2).replace('.', ',') + ' €';
const pedidos = $input.all().map(item => item.json);

// Total de ventas y pedido medio
const totalVentas = pedidos.reduce((suma, p) => suma + p.total, 0);

// Importe por cliente y el mejor
const porCliente = {};
for (const p of pedidos) {
  porCliente[p.cliente] = (porCliente[p.cliente] ?? 0) + p.total;
}
const [mejorCliente, importeMejor] = Object.entries(porCliente)
  .sort((a, b) => b[1] - a[1])[0];

// Unidades por producto, leyendo las líneas de otro nodo
const unidades = {};
for (const item of $('Separar pedidos').all()) {
  for (const l of item.json.lineas) {
    unidades[l.producto] = (unidades[l.producto] ?? 0) + l.unidades;
  }
}
const ranking = Object.entries(unidades)
  .sort((a, b) => b[1] - a[1])
  .map(([producto, uds]) => ({ producto, unidades: uds }));

console.log('Clientes:', porCliente);

return [{
  json: {
    pedidos: pedidos.length,
    total_ventas: r2(totalVentas),
    pedido_medio: r2(totalVentas / pedidos.length),
    mejor_cliente: mejorCliente,
    importe_mejor_cliente: r2(importeMejor),
    ranking_productos: ranking,
    resumen: `Hoy: ${pedidos.length} pedidos y ${euros(totalVentas)} en ventas. ` +
      `Mejor cliente: ${mejorCliente} (${euros(importeMejor)}). ` +
      `Producto estrella: ${ranking[0].producto} (${ranking[0].unidades} uds.).`
  }
}];

Problemas frecuentes

    

      
El nodo Code no saca ningún item y no da error
Estás en Run Once for Each Item y tu código no llega a un return (o devuelve null). En ese modo, un item sin return se descarta en silencio. Revisa que todas las ramas de tu código terminen devolviendo el item.

      
«Code doesn't return items properly»
En All Items falta el return al final o devuelves algo que no es una lista de objetos, por ejemplo return 5 o return ['a', 'b']. Devuelve [{ json: {...} }].

      
«Can't use .all() here»
Usas $input.all(), .first() o .last() en Run Once for Each Item. Cambia el modo a All Items o usa $json para el item actual.

      
«Cannot read properties of undefined (reading '…')»
Lees algo dentro de un campo que no existe en ese item: un nombre mal escrito o un item al que le falta el dato. El mensaje dice la línea y el item. Revisa el panel Input y usa ?. y ?? para los datos opcionales.

      
Los decimales salen raros (47.550000000000004)
Es normal en JavaScript (y en casi todos los lenguajes): los decimales no se guardan exactos. Redondea al final de cada cálculo con Math.round(n * 100) / 100 y, para mostrarlo, usa n.toFixed(2).

      
Después de mi Code, $('Nodo').item da error en otro nodo
En All Items, si devuelves un número distinto de items, n8n no sabe qué item de salida viene de cuál de entrada (el emparejamiento del módulo 5). Usa .first() o .all() en los nodos siguientes, o añade a cada item pairedItem: índice con el item de entrada del que sale: { json: {...}, pairedItem: 0 }.

      
«require is not defined» o «Cannot find module»
Los módulos están desactivados por defecto. En tu instalación, añade al compose.yml la variable NODE_FUNCTION_ALLOW_BUILTIN=crypto (o los que necesites) y reinicia. Y recuerda que fetch no funciona: para llamar a una API usa HTTP Request.
