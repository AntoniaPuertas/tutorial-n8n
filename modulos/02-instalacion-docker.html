Instalar n8n en local con Docker

Al terminar este módulo tendrás n8n funcionando en tu ordenador, en http://localhost:5678, con tus workflows guardados de forma permanente.

¿Qué es Docker y por qué lo usamos?

Docker permite ejecutar programas dentro de contenedores: "cajas" aisladas que traen todo lo necesario para funcionar. Así no tienes que instalar Node.js ni otras dependencias en tu sistema.

Imagen

La "plantilla" del programa, que se descarga una vez. La de n8n se llama n8nio/n8n.

Contenedor

Una copia en marcha de esa imagen. Puedes pararla, borrarla y crearla de nuevo.

Volumen

Un espacio de almacenamiento que sobrevive al contenedor. Ahí guardaremos workflows y credenciales.

Es la vía recomendada por n8n: la instalación mediante npm deja de funcionar a partir de n8n 3.0. Docker, además, se usa igual en Windows, macOS y Linux.

Paso 1 · Instalar Docker

Elige tu sistema operativo:

  1. Docker Desktop necesita WSL 2 (el subsistema de Linux de Windows). Abre PowerShell como administrador y ejecuta:
    PowerShell
    wsl --install
    Reinicia el equipo cuando termine.
  2. Descarga Docker Desktop desde docker.com e instálalo dejando marcada la opción Use WSL 2.
  3. Abre Docker Desktop y espera a que indique que el motor está en marcha (Engine running).
  1. Descarga Docker Desktop desde docker.com. Elige la versión de tu procesador: Apple Silicon (M1, M2, M3…) o Intel.
  2. Abre el archivo .dmg y arrastra Docker a Aplicaciones.
  3. Abre Docker desde Aplicaciones, acepta los permisos y espera a que el icono de la ballena en la barra de menús deje de moverse.

Puedes instalar Docker Desktop para Linux, o bien Docker Engine con el script oficial (habitual en servidores y en Ubuntu/Debian):

Terminal
# Instala Docker Engine y el plugin Docker Compose
curl -fsSL https://get.docker.com | sh

# Permite usar docker sin sudo (cierra sesión y vuelve a entrar después)
sudo usermod -aG docker $USER

Comprueba que todo está bien abriendo una terminal (en Windows, PowerShell) y ejecutando:

Terminal
docker --version
docker compose version

Si ambos comandos muestran un número de versión, Docker está listo.

Paso 2 · ¿Qué versión de n8n instalar?

n8n publica versiones nuevas casi cada semana, en dos canales:

  • Stable: la versión recomendada para el uso diario. Es la que descarga Docker por defecto (n8nio/n8n o n8nio/n8n:latest). En noviembre de 2026 corresponde a la rama 2.49.
  • Beta (n8nio/n8n:next): trae novedades antes, pero puede tener errores.

Ya existe una versión mayor n8n 3.x con cambios incompatibles. Antes de instalar, revisa en las versiones de GitHub cuál es la estable actual. Si quieres que todo coincida exactamente con este tutorial, fija una versión concreta (por ejemplo n8nio/n8n:2.49.6).

Paso 3 · Poner n8n en marcha

Hay dos formas. Te recomendamos la opción B porque guarda la configuración en un archivo y es más fácil de mantener, pero la A es perfecta para una primera prueba.

Primero creamos el volumen donde se guardarán los datos, y después arrancamos el contenedor:

Terminal (macOS / Linux)
docker volume create n8n_data

docker run -it --rm \
  --name n8n \
  -p 5678:5678 \
  -e GENERIC_TIMEZONE="Europe/Madrid" \
  -e TZ="Europe/Madrid" \
  -e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n

En PowerShell la barra invertida \ no sirve para partir líneas; usa el acento grave `:

PowerShell (Windows)
docker volume create n8n_data

docker run -it --rm `
  --name n8n `
  -p 5678:5678 `
  -e GENERIC_TIMEZONE="Europe/Madrid" `
  -e TZ="Europe/Madrid" `
  -e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true `
  -v n8n_data:/home/node/.n8n `
  n8nio/n8n

¿Qué significa cada parte?

  • docker volume create n8n_dataCrea un volumen llamado n8n_data para guardar tus datos.
  • -itModo interactivo: verás los mensajes de n8n en la terminal.
  • --rmBorra el contenedor al pararlo. Tus datos no se pierden porque están en el volumen.
  • --name n8nPone nombre al contenedor para identificarlo fácilmente.
  • -p 5678:5678Conecta el puerto 5678 de tu ordenador con el del contenedor. Por eso abrimos localhost:5678.
  • TZ y GENERIC_TIMEZONEZona horaria del sistema y de los nodos con horario (Schedule). Cámbiala si no estás en España peninsular.
  • N8N_ENFORCE_SETTINGS_FILE_PERMISSIONSProtege el archivo de configuración con permisos seguros.
  • -v n8n_data:/home/node/.n8nMonta el volumen en la carpeta donde n8n guarda workflows, credenciales y la clave de cifrado.
  • n8nio/n8nLa imagen oficial de n8n (versión estable).

Para pararlo, pulsa Ctrl + C en la terminal.

Docker Compose describe los contenedores en un archivo de texto. Así no tienes que recordar comandos largos.

  1. Crea una carpeta para el proyecto y entra en ella:
    Terminal
    mkdir n8n
cd n8n
  2. Dentro, crea un archivo llamado .env con tus ajustes:
    .env
    # Versión de n8n (latest = estable actual; o fija una, p. ej. 2.49.6)
N8N_VERSION=latest
# Zona horaria
TZ=Europe/Madrid
  3. Crea el archivo compose.yml:
    compose.yml
    services:
  n8n:
    image: n8nio/n8n:${N8N_VERSION}
    container_name: n8n
    restart: unless-stopped
    ports:
      - "5678:5678"
    environment:
      - TZ=${TZ}
      - GENERIC_TIMEZONE=${TZ}
      - N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true
    volumes:
      - n8n_data:/home/node/.n8n

volumes:
  n8n_data:
  4. Arranca n8n en segundo plano y comprueba que está en marcha:
    Terminal
    docker compose up -d
docker compose ps
    En la columna STATUS debe aparecer Up.

¿Qué hace cada parte del compose?

  • imageLa imagen y versión a usar; la toma de la variable N8N_VERSION del .env.
  • restart: unless-stoppedArranca n8n solo al encender el ordenador o si se cae, salvo que lo pares tú.
  • portsIgual que -p: expone n8n en localhost:5678.
  • environmentVariables de configuración (zona horaria, permisos).
  • volumesGuarda los datos en el volumen n8n_data para que no se pierdan.

El repositorio oficial de n8n ofrece un compose más completo que añade servicios de sandbox para ejecutar código y un buscador web para el asistente de IA. Es más complejo y requiere varias claves; lo veremos como ampliación en el módulo de IA.

Paso 4 · Primer acceso

  1. Abre el navegador y entra en http://localhost:5678. Los primeros segundos puede tardar mientras n8n arranca.
  2. Crea la cuenta de propietario (owner): email, nombre y contraseña. Esta cuenta solo existe en tu instalación local; guarda bien la contraseña.
  3. Responde (o salta) el breve cuestionario inicial. n8n puede ofrecerte activar gratis funciones extra con una licencia comunitaria a cambio de tu email; es opcional.
  4. Verás la pantalla de Overview con el botón para crear tu primer workflow. ¡n8n ya funciona!

Puedes ver la versión instalada en el menú inferior izquierdo, en Help → About n8n. En el módulo 3 recorreremos el editor con calma.

Actualizar, parar y desinstalar

Con Docker Compose (ejecuta los comandos dentro de la carpeta n8n):

Quiero…Comando
Parar n8ndocker compose stop
Volver a arrancarlodocker compose start
Ver los mensajes (logs)docker compose logs -f n8n
Actualizar a la última versióndocker compose pull y después docker compose up -d
Quitar el contenedor (conserva datos)docker compose down
Borrarlo todo, datos incluidosdocker compose down -v

Cuidado: down -v elimina el volumen con tus workflows y credenciales, y no se puede deshacer. Antes de actualizar a una versión mayor (por ejemplo de 2.x a 3.x), exporta tus workflows y lee la guía de cambios incompatibles.

Opcional · Usar PostgreSQL

Por defecto n8n guarda todo en SQLite, un archivo dentro del volumen. Para aprender es más que suficiente. Si más adelante quieres una base de datos más robusta, este compose.yml añade PostgreSQL:

compose.yml con PostgreSQL
services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      - POSTGRES_USER=${POSTGRES_USER}
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
      - POSTGRES_DB=${POSTGRES_DB}
    volumes:
      - pg_data:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 5s
      retries: 10

  n8n:
    image: n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    ports:
      - "5678:5678"
    environment:
      - TZ=${TZ}
      - GENERIC_TIMEZONE=${TZ}
      - N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true
      - DB_TYPE=postgresdb
      - DB_POSTGRESDB_HOST=postgres
      - DB_POSTGRESDB_PORT=5432
      - DB_POSTGRESDB_DATABASE=${POSTGRES_DB}
      - DB_POSTGRESDB_USER=${POSTGRES_USER}
      - DB_POSTGRESDB_PASSWORD=${POSTGRES_PASSWORD}
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

volumes:
  n8n_data:
  pg_data:

Y añade al .env (cambia la contraseña por una tuya):

.env
POSTGRES_USER=n8n
POSTGRES_PASSWORD=cambia-esta-clave
POSTGRES_DB=n8n

Aunque uses PostgreSQL, mantén el volumen n8n_data: ahí está la clave de cifrado de tus credenciales. Si la pierdes, n8n no podrá leerlas.

Problemas frecuentes

«Cannot connect to the Docker daemon» o «docker: command not found»

Docker no está arrancado o no está instalado. Abre Docker Desktop y espera a que el motor esté en marcha. En Linux, prueba sudo systemctl start docker.

«port is already allocated» (el puerto 5678 está ocupado)

Otro programa (o otro contenedor de n8n) usa ese puerto. Cambia la parte izquierda del mapeo, por ejemplo "5679:5678", y entra en localhost:5679. Para ver contenedores en marcha: docker ps.

En Windows Docker Desktop no arranca

Comprueba que WSL 2 está instalado (wsl --status) y que la virtualización está activada en la BIOS/UEFI. Actualiza WSL con wsl --update.

«permission denied» al usar docker en Linux

Tu usuario no está en el grupo docker. Ejecuta sudo usermod -aG docker $USER, cierra sesión y vuelve a entrar.

Los workflows programados se ejecutan a una hora incorrecta

Revisa GENERIC_TIMEZONE y TZ. Además, cada workflow tiene su propia zona horaria en Settings del workflow.

He perdido mis workflows al reiniciar

Probablemente arrancaste el contenedor sin el volumen (-v n8n_data:/home/node/.n8n). Añádelo siempre. Para ver tus volúmenes: docker volume ls.
